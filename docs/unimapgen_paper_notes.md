# UniMapGen 论文要点摘录（复现导向）

## 1. 任务与核心机制

1. 输入模态
- 卫星图（BEV）
- 车载图像（PV）
- 文本提示（Text）

2. 输出形式
- 以自回归方式生成矢量地图 token 序列（点序列 + 类别 + 端点属性）。

3. 关键表示
- 地图线采用序列化表示。
- 端点包含 `start/end/cut` 语义，用于跨 patch 状态更新。
- 坐标与角度离散化为高分辨率 bins（论文为 10k 量化）。

4. 状态更新
- 通过上一状态地图 `G_{n-1}` 与当前观测共同预测 `G_n`。
- 属于增量式地图生成，不是单 patch 独立预测。

## 2. 训练流程（论文）

1. Stage 1
- 以地图生成相关任务做预训练（含图文到地图与地图补全）。

2. Stage 2
- 结合配对数据做视觉-语言-地图能力对齐。

3. Stage 3
- 引入状态更新训练，学习连续 patch 的全局增量构图。

> 复现落地建议：先保证 Stage1/2 的生成稳定，再进入 Stage3；否则状态更新很容易塌缩。

## 3. 评测关注点

1. 几何精度
- Chamfer / mAP / IoU 相关指标。

2. 连续性
- 端点连接质量、跨 patch 连通性。

3. 多模态鲁棒性
- BEV/PV/Text 任意组合下性能变化。

## 4. 对当前工程的直接约束

1. Tokenizer 必须支持高分辨率量化（本仓库已补 `coord_num_bins/angle_num_bins`）。
2. 训练脚本必须支持阶段衔接（本仓库已补 `train.init_checkpoint`）。
3. 状态更新实验要与非状态更新实验成对对比（本仓库已新增对应 smoke 配置）。
