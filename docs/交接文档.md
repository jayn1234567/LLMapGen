## 一、项目概述

基于多模态 Qwen/LLaVA 兼容架构的 BEV 道路几何重建模型，使用 **DINOv2/DINOv3** 作为视觉编码器 + **Qwen2/Qwen3/Qwen3-VL** 作为语言模型，完成 BEV 道路中心线预测，并支持后续 lane+intersection 与 GRPO 强化学习流程。

- **当前 NPU/debug 环境**: conda `unimapgen`
- **旧 GPU/历史环境**: conda `fastvlm`
- **依赖**: transformers>=4.51.0, deepspeed>=0.14.4

### 当前版本补充（2026-05-22）

旧章节里部分脚本名来自历史版本。当前有效入口以 `scripts/README.md`、
`scripts/debug/README.md`、`docs/PROJECT_STRUCTURE.md` 为准，关键点如下：

- 当前主框架代码在 `mllm/`，`llava/` 名称主要是历史兼容。
- 数据处理入口在 `data_process/`，会生成 `phase_a/{train,eval,test}.jsonl` 和 `phase_b/{train,eval,test}.jsonl`。
- `phase_a` 是单 patch 识别；`phase_b` 是 state-update，使用左/上邻 patch 的 continuity hints。
- lane+intersection 数据处理中，缺失或为空的 `Intersection.geojson` 不再过滤样本，会作为“只有 lane、没有路口目标”的负样本保留。
- 新数据默认使用 `coord_mode=norm1000`；推理、可视化和指标会转回 pixel/meter 空间再评估。
- NPU SFT 正式入口在 `scripts/npu/train/train_sft_stage_*_npu.sh`，底层调用 `run_sft_nodeepstack_npu.sh` 或对应 base recipe。
- NPU GRPO 正式入口在 `scripts/npu/train/train_grpo_stage_*_npu.sh`，使用 vLLM-Ascend 的 prompt-embedding rollout，不是 HF-local generation。
- NPU 推理入口在 `scripts/npu/test/test_stage_*_npu.sh`，输出 `summary.json`、`json/`、`viz/`、`eval.json`、`whole_map_viz/`。
- 本地 NPU 小样本 debug 入口在 `scripts/debug/`，包括 SFT、GRPO、推理和一键流程。

### 当前 checkpoint 策略

- 普通 step 权重仍由 `SAVE_STEPS` 和 `SAVE_TOTAL_LIMIT` 控制，保存为 `checkpoint-*`。
- SFT 的 eval-best 由 `SAVE_BEST_EVAL_LOSS=True`、`EVAL_STEPS`、`BEST_EVAL_LOSS_DIR=eval_best` 控制。
- SFT 的 train-loss best 由 `SAVE_BEST_TRAIN_LOSS`、`BEST_TRAIN_LOSS_START_STEP`、`BEST_TRAIN_LOSS_DIR=best` 控制。
- NPU 云端默认使用 `BEST_CHECKPOINT_SAVE_MODE=rotating_create_only`，best 权重写到 `eval_best_candidates/` 或 `best_candidates/`，写完 `_SUCCESS` 才算有效，避免云盘 rename/replace 权限问题。
- 推理和 GRPO 加载 SFT 权重时优先级是：`eval_best` / `eval_best_candidates` → `best` / `best_candidates` → 最新 `checkpoint-*`。
- GRPO 自己维护 `best_reward/` 和最终 `merged/`；`merged/` 是推荐用于后续推理或二次训练的自包含权重。

## 三、模型架构

### 数据流

```
DINOv2/DINOv3 ViT (frozen, output_hidden_states=True)
    │
    ├── Layer 22 (select_layer=-2) → feature_select → mm_projector (MLP)
    │       │
    │       └── 替换 <image> token → LLM embedding 层
    │
    └── DeepStack: selected ViT layers → 独立 merger → 残差注入 LLM

DeepStack 注入（按 merger 索引 → LLM layer）:
    merger[0] (ViT Layer 18) → LLM Layer 0 pre-hook: hs += scatter(...)
    merger[1] (ViT Layer 12) → LLM Layer 1 pre-hook: hs += scatter(...)
    merger[2] (ViT Layer 6)  → LLM Layer 2 pre-hook: hs += scatter(...)
```

### DeepStackMerger 结构

```
LayerNorm(vit_dim) → Linear(vit_dim → llm_dim) → GELU → Linear(llm_dim → llm_dim)
```

每层独立 merger，不共享权重。

### DINOv2 vs DINOv3 关键差异

| | DINOv2-L | DINOv3-L |
|---|---|---|
| 模型类 | Dinov2Model | DINOv3ViTModel |
| patch_size | 14 | 16 |
| 位置编码 | 绝对嵌入 | RoPE |
| register tokens | 0 | 4 |
| skip_tokens | 1 (CLS) | 5 (CLS+4) |
| image_size | 518 | 224 |

## 五、测试/推理

### 推理入口：`scripts/tools/infer_centerline_checkpoint.py`

#### 加载流程

```
1. config.json → model_type → LlavaQwen2ForCausalLM / LlavaQwen3ForCausalLM
2. builder.py → mm_vision_tower_type 优先 → 选择 DINOv2/V3VisionTower
3. vision_tower.load_model() → 从 base 路径加载 ViT 结构 + image_processor
4. checkpoint model.safetensors → load_state_dict → 覆盖所有权重
5. model.to(device) → 放到 NPU/GPU
6. generate() → BEV 图像 → 道路中心线 JSON
```

#### 加载优先级（`builder.py`）

```
config.mm_vision_tower_type == "dinov3" → DINOv3VisionTower     ← 训练时写入，最可靠
config.mm_vision_tower_type == "dinov2" → DINOv2VisionTower
路径包含 "dinov3"                       → DINOv3VisionTower     ← fallback
路径包含 "dinov2"                       → DINOv2VisionTower     ← fallback
```

#### 测试脚本

| 脚本 | 环境 | 说明 |
|------|------|------|
| `scripts/gpu/test_qwen3.sh` | GPU 8卡 | 单独下载 checkpoint + DINOv2 base |

## 六、DeepSpeed 配置说明

### 主力配置：`deepspeed_zero3_no_merge.json`

```json
"gather_16bit_weights_on_model_save": false
```

- 训练时**不聚拢权重**到单卡保存 → 避免 OOM
- 每个 rank 独立保存分片到 checkpoint 目录
- 训练结束后 shell 脚本自动运行 `zero_to_fp32.py` 合并分片 → `model.safetensors`
- 合并时设置 `TORCH_FORCE_WEIGHTS_ONLY_LOAD=0`（绕过 torch 2.5+ 的 weights_only 限制）

### 替代配置：`deepspeed_zero3.json`

```json
"gather_16bit_weights_on_model_save": true
```

- 保存时聚拢权重到单卡 → 可能 OOM（仅小模型用）

## 七、关键代码路径

### 视觉编码器类型选择（`llava/model/multimodal_encoder/builder.py:26-34`）

```python
vit_type = getattr(vision_tower_cfg, 'mm_vision_tower_type', '')
if vit_type == "dinov3":
    return DINOv3VisionTower(vision_tower, args=vision_tower_cfg)
if vit_type == "dinov2":
    return DINOv2VisionTower(vision_tower, args=vision_tower_cfg)
# fallback: path-based detection
```

### DeepStack 注入（`llava/model/language_model/llava_qwen3.py:56-99`）

通过 PyTorch `register_forward_pre_hook`，在 LLM Layer 0/1/2/3 前向**之前**，将 DeepStack 特征**残差叠加**到 hidden_states：

```python
hs = hs + scattered    # residual addition, NOT replacement
```

### DINO 配置注册表（`llava/model/multimodal_encoder/dino_config.py`）

| 配置 key | hidden_size | patch_size | image_size | register_tokens | deepstack_indexes |
|----------|------------|------------|------------|-----------------|-------------------|
| dinov2-large | 1024 | 14 | 518 | 0 | [6,12,18,23] |
| dinov3-vitl16 | 1024 | 16 | 224 | 4 | [6,12,18,23] |
| dinov3-vitb16 | 768 | 16 | 224 | 4 | [3,6,9,11] |

自动检测：优先使用 checkpoint/config 中的 `mm_vision_tower_type`；否则从 `--vision_tower` 路径里的明确 DINO key/别名自动选配置。
手动覆盖输入尺寸：`--input_image_size 448`。

## 八、已解决的常见问题

| 问题 | 原因 | 修复 |
|------|------|------|
| `Unknown vision tower: ` | 脚本变量名不匹配 (DINOV2_PATH vs DINOV3_PATH) | 统一变量名 |
| `ZeroStageEnum unpickle` | torch 2.5+ 默认 weights_only=True | `TORCH_FORCE_WEIGHTS_ONLY_LOAD=0` |
| 推理时全部 ViT 权重 UNEXPECTED | builder.py 只看路径字符串选 ViT 类型 | 优先读 `mm_vision_tower_type` |
| 推理时 2048 token 全部输出 | self-contained checkpoint 的 ViT 随机初始化 | 改用 base 路径加载 ViT 结构 |
| 推理时 `npu:0 and npu:1` | 手动 `vt.to()` 与 device_map=auto 冲突 | 删除手动设备移动 |
| 非 node 0 节点 checkpoint 丢失 | 多节点写入不同路径 | 所有节点 OUTPUT_PATH=$OSB_SHARE_PATH |
| PYTORCH_NPU_ALLOC_CONF 导致 OOM | 限制内存分配器拆分大块 | 删除该环境变量 |
| DDP 报未使用参数 | LoRA 后创建 DeepStack merger | LoRA 时冻结 merger 或调整顺序 |

## 十一、重要注意事项

1. **NPU 脚本**需要设置 ASCEND 环境变量 + HCCL backend，见 `scripts/npu/*_npu.sh` 前 30 行即可。
2. **ZeRO-3 多节点**：所有节点必须写同一个 OBS 共享路径（`OUTPUT_PATH=$OSB_SHARE_PATH`），否则只有 node 0 的分片。
3. **全参微调 checkpoint**：训练时会自动保存 `preprocessor_config.json` 和 `vit_config.json` 到 checkpoint 目录（`llava_trainer.py:_save_vit_assets`）。推理时如果 ViT base 路径不可访问，能从 checkpoint 加载 image_processor。
4. **DDP 模式**（非 DeepSpeed）配合 LoRA + DeepStack 时，需要确保 DeepStack merger 在 LoRA 之前创建，或者冻结 merger 参数。
5. **OBS 环境**：脚本使用 moxing 下载/上传，`OUTPUT_URL` 由平台注入。
